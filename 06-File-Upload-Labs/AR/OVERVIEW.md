# ثغرات رفع الملفات (File Upload Vulnerabilities) — دليل شامل وموسع

[![التصنيف](https://img.shields.io/badge/CWE-CWE--434-red)]()

---

## 1. ما هي ثغرة رفع الملفات؟
تحدث ثغرة **رفع الملفات (File Upload)** عندما يسمح التطبيق للمستخدم برفع ملف إلى السيرفر دون التحقق الكافي من اسمه، نوعه، امتداده، أو محتواه، ويقوم بحفظ هذا الملف في مجلد يمكن الوصول إليه عبر المتصفح وقابل للتنفيذ (Executable Web Directory).

تعتبر هذه الثغرة من أخطر ثغرات الويب لأنها تؤدي في معظم الحالات إلى **تنفيذ أوامر عن بُعد (Remote Code Execution - RCE)** عبر رفع سكربت خبيث (Web Shell) وتشغيله للسيطرة التامة على الخادم.

---

## 2. طبقات فحص الملفات وكيف يتجاوزها المهاجم

| طبقة الفحص | آلية عمل الفلتر | كيف يتجاوزها المخترق؟ |
|---|---|---|
| **فحص الواجهة (Client-Side)** | كود جافاسكربت في المتصفح يمنع اختيار غير الصور. | تعطيل الجافاسكربت أو اعتراض الطلب في Burp Suite بعد الاختيار. |
| **فحص نوع المحتوى (MIME-Type)** | فحص ترويسة `Content-Type: image/jpeg`. | تعديل الترويسة في Burp Suite من `application/x-php` إلى `image/jpeg`. |
| **القوائم السوداء للامتداد (Blacklist)** | حظر امتداد `.php` فقط. | استخدام امتدادات بديلة (`.phtml`, `.php5`) أو رفع ملف `.htaccess` لتغيير الإعدادات. |
| **فحص مسار الحفظ (Upload Path)** | مجلد الرفع غير مصرح بتشغيل السكربتات. | دمج ثغرة Path Traversal في اسم الملف (`..%2fexploit.php`) لرفعه في مجلد تنفيذي! |
| **فحص الامتداد الظاهري** | فحص أن الاسم ينتهي بـ `.jpg`. | حقن البايت الصفري (`exploit.php%00.jpg`) لاقتطاع الامتداد المزيف في السيرفر. |
| **فحص البايتات السحرية ومكتبات الصور** | فحص محتوى الصورة بالكامل بواسطة مكتبة برمجية. | إنشاء ملف صورة هجين (Polyglot) سليم 100% ويحتوي على كود PHP في الـ EXIF. |
| **الفحص بعد الحفظ (Race Condition)** | حفظ الملف ثم فحصه ومسحه إذا كان خبيثاً. | استغلال النافذة الزمنية الضئيلة وطلب تنفيذ الملف قبل أن يحذفه السيرفر بالتوازي. |
