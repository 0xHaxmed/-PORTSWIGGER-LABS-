# دليل الحماية والإغلاق لحقن أوامر النظام (Remediation)

## 1. خط الدفاع الأول: تجنب استدعاء أوامر النظام نهائياً
الوسيلة الأكثر أماناً لمنع الثغرة هي عدم استدعاء أوامر الشل إطلاقاً، واستخدام الدوال البرمجية المدمجة في لغة البرمجة نفسها:
- بدلاً من `rm -rf` استخدم `os.remove()`.
- بدلاً من `mail` استخدم مكتبات SMTP الجاهزة.

---

## 2. خط الدفاع الثاني: استدعاء البرامج كمعاملات منفصلة (بدون شل)
إذا كان استدعاء برنامج تنفيذي خارجياً أمراً حتمياً، يجب استدعاؤه مباشرة كملف تنفيذي مع تمرير المتغيرات كمصفوفة (Array / List)، **دون تشغيل مفسر الشل**:

### كود آمن بلغة Python:
```python
import subprocess

# آمن تماماً: shell=False تلقائياً، والمتغيرات تمرر كمصفوفة.
# حتى لو احتوى store_id على | أو ; سيتعامل معها النظام كحروف نصية عادية!
result = subprocess.run(
    ["/usr/local/bin/check_stock", store_id, product_id],
    capture_output=True,
    text=True,
    shell=False
)
```

### كود آمن بلغة Node.js:
```javascript
const { execFile } = require('child_process');

// آمن: execFile لا يستدعي /bin/sh
execFile('/usr/local/bin/check_stock', [storeId, productId], (err, stdout, stderr) => {
    // معالجة النتيجة
});
```

## 3. الفلترة الصارمة بالقوائم البيضاء (Allow-lists)
إذا كان المدخل المفترض رقماً (مثل ID)، يجب التحقق بتعبير نمطي صارم:
`preg_match('/^[0-9]+$/', $storeId)`
ورفض الطلب بالكامل في حال وجود أي حرف غير رقمي.
